# Чек-листы на стороне Doc-V

Вся Doc-V-часть выполняется администратором руками. Сервис при этом уже
развёрнут на 25353 (deploy/README-deploy.md), старый на 25351 живёт до
конца переключения.

## 0. Токены (один раз, до переключения)

1. Сгенерировать GW_TOKEN_DOCV, вписать в .env шлюза, перезапустить юнит.
2. В карточке НАСТРОЙКИ завести setting-поле «Токен шлюза» и вписать туда
   то же значение. Действия будут подставлять его в заголовок из поля.

## 1. Переключение реестров (веха M2) — 4 действия «HTTP-запрос»

По одному, с наблюдением после каждого. Старые URL -> новые:

| Тип, точка | Было | Стало |
|---|---|---|
| Реестр платежей, «Отправка данных (внутренний реестр)» | :25351/form_inner_registry | :25353/render/registry/inner |
| Реестр платежей, «Отправка данных (внешний реестр)» | :25351/form_outer_registry | :25353/render/registry/outer |
| Реестр платежей, «Отправка данных (реестр предстоящих платежей)» | :25351/form_priority_registry | :25353/render/registry/priority |
| Реестр предстоящих платежей, «Отправка данных (реестр предстоящих платежей)» | :25351/form_priority_registry | :25353/render/registry/priority |

В каждом действии добавить HTTP-заголовок: название `Authorization`,
значение из поля «Токен шлюза» НАСТРОЕК с приставкой `Bearer ` —
если редактор заголовков не умеет «Bearer + поле», завести в НАСТРОЙКАХ
поле сразу со значением `Bearer <токен>`.

Тело и разбор ответа не меняются: тот же JSON, в ответе тот же
`download_url`. Скачивание файла по URL из поля работает как раньше
(GET /files/* токена не требует).

Откат любого шага — вернуть старый URL: старый сервис живёт.

## 2. Точка опроса очереди (веха M5) — тип «Шлюз»

1. Служебный тип документа «Шлюз», один документ, доступ только админам.
2. Точка «Опрос», на неё — действия по порядку:
   1) «HTTP-запрос»: GET `http://192.168.30.19:25353/jobs/pending?consumer=docv&limit=20`,
      заголовок Authorization как выше, ответ в JSON-поле «Задания».
   2) «Условие»: «Задания» пусто или `[]` -> стоп (эта ветка срабатывает
      в 99% прогонов, после неё не должно быть ни одного действия).
   3) Разбор: для каждого задания — «Выборка» по полю «job_id» среди уже
      созданных документов (дедуп), затем «Создание» из JSON; в создаваемый
      документ обязательно инициализировать поле с job_id.
   4) «HTTP-запрос»: POST `.../jobs/ack`, тело `{"ids": [...]}` из поля.
3. Планировщик задач: запуск точки «Опрос» каждые 30 секунд.
   ВАЖНО: интервал живёт в серверном «Планировщике задач» и НЕ попадает
   в экспорт конфигурации — зафиксировать в вики.
4. Продюсерам (1С и др.) выдать их токены (GW_PRODUCER_TOKENS в .env).

Семантика: at-least-once. Если ack не дошёл, задание выдастся повторно
через 60 с — дубль обязан гаситься выборкой из шага 3.

## 3. Операции /ops (веха M4)

Токен GW_TOKEN_OPS — отдельный, тоже в НАСТРОЙКИ (отдельное поле).
Вызов: «HTTP-запрос» POST `http://192.168.30.19:25353/ops/<имя>`,
тело — JSON-поле вида `{"params": {...}}`, ответ в JSON-поле; успех
проверять условием по `ok`, а не по коду HTTP (он всегда 200).
Список операций: GET /ops. Порождённые файлы приходят в `files[]`
ссылками download_url.

## 4. Вывод старого сервиса (веха M6)

Все 4 действия переведены и неделю стабильны ->
`systemctl disable --now excelium.service` на 192.168.30.19, архив
каталога api_excel. Порт 25351 не переиспользовать.
