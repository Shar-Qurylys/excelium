# Doc-V Gateway

Шлюз между Doc-V (192.168.30.29) и всем, что Doc-V делать не умеет или
умеет только за деньги. Работает на 192.168.30.19:25353, разговаривает с
Doc-V единственным бесплатным действием «HTTP-запрос».

Что делает:

- **Реестры платежей** — Excel по JSON из Doc-V: внутренний, внешний,
  реестр предстоящих платежей.
- **Подписанты** — шлюз сам знает, кто подписывает реестр этой компании,
  и печатает готовые строки вместо скрытых листов-справочников.
- **Документы Typst** — PDF по шаблонам, которые правятся прямо в
  веб-интерфейсе; карточка договора с листом согласования.
- **Операции** — команды на сервере из белого списка `ops.yaml`
  (замена платного действия «Запуск»).
- **Справочники из Doc-V** — сотрудники (`structura`), должности
  (`positions`) и подразделения (`departments`) шлюз сам забирает из
  REST-шлюза restgw рядом с Doc-V и подставляет должности и ФИО в
  документы. Подробнее — ниже.
- **Очередь заданий** — API `/jobs` остаётся (Doc-V опрашивает
  `/jobs/pending`), но в веб-интерфейсе раздела заданий больше нет:
  это не ответственность шлюза.
- **Веб-интерфейс** `/ui` — журнал событий, справочники, файлы,
  подписанты, шаблоны, история операций, настройки.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
cp .env.example .env          # заполнить токены, chmod 600
.venv/bin/python -m uvicorn gateway.main:app --port 25353
.venv/bin/python -m pytest -q
```

## Справочники из Doc-V

Doc-V сам собирает наборы данных и пересобирает их при каждом изменении
справочника; отдаёт их сервис restgw на сервере Doc-V (192.168.30.29):
`GET <GW_RESTGW_URL>/v1/data/{имя}` с заголовком `X-API-Key`. Шлюз
забирает набор и полностью замещает свой справочник:

- при старте сервиса — все три набора (в фоне, старт не ждёт);
- по сигналу Doc-V — `POST /directory/{имя}/refresh` с токеном docv,
  Doc-V вызывает его после каждой пересборки набора; ответ
  `{"directory": имя, "items": N, "updated_at": ...}`;
- по кнопке «Обновить из Doc-V» в /ui → «Обзор».

Если restgw недоступен или ответил ошибкой, прежний справочник остаётся,
причина пишется в журнал (событие «Справочник не забран из restgw»), а
refresh отвечает 502 с текстом `{"error": "..."}`. Пустой набор не
затирает непустой справочник. Опроса по расписанию нет.

Нужны две переменные в `.env` (без них забор выключен):

| Переменная | Что |
|---|---|
| `GW_RESTGW_URL` | адрес restgw без `/v1/data`, например `http://192.168.30.29:<порт>` |
| `GW_RESTGW_KEY` | ключ restgw с областью data; в журналы не пишется |

Старый приём `POST /directory/{имя}` работает как раньше — им пока
пользуется тип «Шлюз» в Doc-V.

Разбор конфигурации и юнита — [deploy/README-deploy.md](deploy/README-deploy.md),
настройка на стороне Doc-V — [deploy/README-docv.md](deploy/README-docv.md).

## Данные, которых нет в git

Живут только на сервере, `git pull` их не трогает:

| Что | Где | Зачем |
|---|---|---|
| Токены, ключ restgw | `.env` | секреты |
| Файлы, база, журналы, состав подписантов | `var/` | состояние сервиса |

Состав подписантов — персональные данные, поэтому живёт в базе на
сервере и правится в /ui → «Подписанты». Резерв — «Скачать JSON» там же;
перед каждым импортом копия ложится в Файлы закреплённой. В git состава
нет; `tests/data/signers_seed.yaml` — только для тестов.
